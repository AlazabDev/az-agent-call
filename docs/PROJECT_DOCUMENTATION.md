# دليل مشروع مركز اتصال وكلاء العزب الذكاء الاصطناعي
**Az Agent Call Center v3.0.1**

يمثل هذا المستند توثيقاً شاملاً لكافة تفاصيل النظام، هيكليته، وظائفه، وطريقة عمله. يُستخدم هذا المشروع كلوحة تحكم (Control Plane) وبوابة اتصال مركزية (MCP Gateway) لوكلاء الذكاء الاصطناعي (AI Agents) التابعين لشركة العزب.

---

## 1. نظرة عامة على النظام (Overview)

تم تصميم النظام ليكون حلقة الوصل المركزية بين وكلاء الذكاء الاصطناعي (AI Agents) والأنظمة التشغيلية المختلفة (مثل البريد الإلكتروني، الاتصالات، ونظام دفتره المحاسبي). يوفر النظام:
- **واجهة إدارة (Admin UI):** للتحكم في الإعدادات، القوالب، وسجلات الوكلاء.
- **بوابة MCP:** واجهة برمجية موحدة (API) تتيح للوكلاء تنفيذ الإجراءات بشكل آمن.
- **ربط محاسبي:** تكامل مباشر مع نظام Daftra ERP.

---

## 2. هيكلية النظام (Architecture)

يتكون النظام من عدة طبقات متكاملة:

- **الواجهة الأمامية (Admin UI):** مبنية باستخدام React، Vite، و TypeScript. تعتمد على مكتبة مكونات `shadcn/Radix` وتوفر تجربة مستخدم متكاملة لإدارة النظام.
- **بوابة الاتصال (MCP Gateway):** تطبيق Node.js يستقبل طلبات الوكلاء عبر المسار `POST /mail` أو `POST /call`.
- **قاعدة البيانات:** يعتمد النظام على **Supabase** (PostgreSQL) لتخزين البيانات، القوالب، وسجلات التدقيق (Audit Logs).
- **خدمة البريد (SMTP):** يتم إرسال رسائل البريد الإلكتروني للوكلاء باستخدام خوادم **Migadu** عبر بروتوكول STARTTLS (المنفذ 587).

---

## 3. المصادقة والصلاحيات (Authentication)

يتبنى النظام نموذج مصادقة صارم يفصل بين المستخدمين البشريين ووكلاء الذكاء الاصطناعي:

### أ. مصادقة الإدارة (Admins)
- تتم حماية المسار `/admin/` باستخدام مصادقة أساسية (HTTP Basic Auth) من خلال خادم Node.js لمنع الوصول غير المصرح به لواجهة تسجيل الدخول.
- بعد الدخول، يتم استخدام نظام Supabase Auth (البريد وكلمة المرور) مع نظام صلاحيات مركزي (RBAC).

### ب. مصادقة الوكلاء (Agents)
- يستخدم الوكلاء رموز مصادقة ثابتة (Bearer Tokens) في ترويسة الطلب `Authorization: Bearer <token>`.
- يتم تخزين الرموز الصريحة في ملف آمن `/var/lib/az-agent-call/data/agent-tokens.json`.
- يتم تحديد هوية الوكيل (Agent ID / Foundry ID) على الخادم (Server-side) ولا يمكن للوكيل تغيير هويته عن طريق مدخلات الطلب.

---

## 4. وظائف وأدوات النظام (MCP Tools)

يوفر النظام مجموعة من الأدوات (Tools) لوكلاء الذكاء الاصطناعي، مقسمة حسب المجال:

### 4.1. أدوات النظام الأساسية (System & Templates)
- `whoami`: تعيد هوية الوكيل المصادق عليه، حالة البريد، والبيانات الوصفية للاتصال.
- `list_templates`: تعرض قائمة بجميع قوالب الرسائل المتاحة (144 قالباً).
- `get_template_schema`: تجلب هيكل البيانات (المتغيرات المطلوبة) لقالب محدد.
- `render_template`: تقوم بتجهيز القالب بالبيانات دون إرساله فعلياً.
- `send_template_email`: ترسل بريداً إلكترونياً باستخدام قالب محدد ومعتمد.
- `send_email`: إرسال بريد إلكتروني نصي حر (موضوع + محتوى HTML).

### 4.2. أدوات التكامل المحاسبي (Daftra ERP)
- `daftra_get_client`: البحث عن عميل في نظام دفتره باستخدام رقم الهاتف، البريد، أو الاسم.
- `daftra_create_invoice`: إنشاء فاتورة مبيعات جديدة لعميل.
- `daftra_list_invoices`: جلب وفلترة فواتير العميل (مدفوعة، غير مدفوعة، متأخرة).
- `daftra_record_payment`: تسجيل دفعة مالية على فاتورة معينة.
- `daftra_check_inventory`: التحقق من المخزون وتوفر المنتجات/الخدمات والأسعار.

### 4.3. أدوات الاتصال (Telephony)
- يتم تحضير أدوات مثل `make_call` و `get_call_transcript` للعمل مع مزودي خدمات الاتصال الصوتي.

---

## 5. قواعد البيانات والجداول (Database Schema)

يحتوي مشروع Supabase على الجداول التالية لإدارة حالة النظام:
- `call_agents`: بيانات الوكلاء ومعرفاتهم.
- `call_templates`: قوالب البريد والرسائل (Shared Templates).
- `call_logs`: سجلات التدقيق لجميع العمليات والأحداث التي يقوم بها الوكلاء.
- `call_settings`: إعدادات النظام العامة.
- `call_admins`: قائمة المسؤولين وصلاحياتهم.
- `call_gateway_instances`: تتبع الخوادم الفعالة (Heartbeat).
- `call_agent_connections`: سجلات اتصال الوكلاء وحالتهم.
- `call_agent_stats`: إحصائيات الاستخدام والأداء.

---

## 6. إعدادات النشر والبيئة (Deployment)

تم تصميم النظام ليعمل على خوادم Bare-metal باستخدام `systemd` و `Nginx`.

### المسارات الرئيسية:
- مسار التطبيق: `/var/www/apps/az-agent-call`
- مسار البيانات الدائمة: `/var/lib/az-agent-call/data`
- ملف البيئة: `/var/www/apps/az-agent-call/.env.local`

### نقاط النهاية (Endpoints):
- **واجهة الإدارة:** `https://agent-call.alazab.com/admin/`
- **بوابة الوكلاء (MCP):** `https://agent-call.alazab.com/mail`
- **فحص الصحة (العام):** `https://agent-call.alazab.com/healthz`
- **فحص الجاهزية (الداخلي فقط):** `http://127.0.0.1:3300/readyz`

### خطوات النشر التلقائي:
يتم النشر عبر تشغيل السكربت `sudo ./deploy/install-production.sh` والذي يقوم بـ:
1. تثبيت الاعتمادات.
2. بناء المشروع (Build).
3. إعداد خدمة `systemd` (`az-agent-call.service`).
4. فحص اتصال البريد (SMTP) لجميع الوكلاء (12 وكيل).
5. إعداد وربط خادم Nginx وتفعيل شهادات SSL.
